# Journal

Chronological log of actions, bugs, and direction changes. Newest at the bottom.

## 2026-09-12

- Read the challenge spec. Found Xcode is not installed on this machine and only 9.7 GB of disk is free. Xcode plus an iOS simulator runtime needs roughly 25 GB. Plan reordered so all TypeScript work (scaffold, timer core, UI, bridge interface) happens before anything that needs Xcode.
- Created the repo with the spec copied to `docs/CHALLENGE.md`.
- Scaffolded with `create-expo-app --template blank-typescript`. Got Expo SDK 57, React Native 0.86, TypeScript 6. Dropped the Android and web config since the challenge is iOS only.
- Added `jest-expo` and `expo-dev-client`. `npx expo install --dev` did not honor the dev flag and put Jest into `dependencies`; moved it by hand.
- Step 2, timer core. A feature-builder subagent wrote `src/timer/` test-first (reducer with start/pause/resume/stop, `elapsedMs`, `formatHHMMSS`). Reviewed in the main thread and changed one thing: the agent clamped the whole elapsed value at zero on clock rollback, which would discard already-accumulated time. Changed to clamp only the running delta, in both `elapsedMs` and the `pause` transition, and adjusted the tests.
- Bug: `npm run typecheck` could not see Jest globals even with `@types/jest` installed. Cause: TypeScript 6 no longer auto-includes `@types/*`; fixed by adding `"types": ["jest"]` to `tsconfig.json`. Also pinned `@types/jest` to 29 to match Jest 29.
- Step 3, UI and bridge interface. Two feature-builder subagents ran in parallel: one built `useTimer` and `TimerScreen`, the other built `liveActivityState.ts` (the data contract the Swift widget will mirror), `modules/live-activity/index.ts` (TypeScript bridge with no-op fallback when native is absent), and AsyncStorage persistence with a hand-written shape guard. Integrated in the main thread by rewriting `useTimer` to hydrate from storage, save every transition, and mirror transitions to the Live Activity (start on new session, update on pause/resume, end on stop). Added a `hydrate` reducer action for that.
- Bug in my own spec, caught by the subagent: I gave the running-state example as `timerStartMs: 7000` for `runningSince 10000, accumulatedMs 5000, now 12000`. The correct value is 5000 (`runningSince - accumulatedMs`). The agent implemented `now - accumulatedMs` to match my number, which would only be right at the instant of start. Fixed the formula to `runningSince - accumulatedMs` and dropped the unused `now` parameter.
- Environment: Xcode 26.6 installed. Downloaded the iOS 26.5 simulator runtime with `xcodebuild -downloadPlatform iOS`; Xcode's own parallel download then failed as a duplicate, so the dead image was deleted with `simctl runtime delete`.
- Blocker: CocoaPods will not install on the system Ruby 2.6 (`securerandom` needs Ruby 3.1+). Needs Homebrew, which requires the user's password to install.
- Constraint noted: no physical device; everything is verified in the simulator, which the spec allows.
- CocoaPods resolved: user installed Homebrew, `brew install cocoapods` gave 1.17. `npx expo prebuild --platform ios` then succeeded (94 pods). Prebuild changed the `ios` npm script to `expo run:ios`; kept.
- Simulator runtime detour: the iOS 26.5 image downloaded by `xcodebuild -downloadPlatform` registered as Ready but never mounted (`/Library/Developer/CoreSimulator/Volumes` stayed empty, devices reported "runtime profile not found"). Likely caused by Xcode's UI download racing the CLI download. Restarting `simdiskimaged` cleared the registration and the asset entirely instead of mounting it. Re-downloading with `-exportPath ~/Downloads/ios-simulator-runtime` so the `.dmg` persists and can be added with `simctl runtime add`.
- Runtime fixed: re-downloaded with `-exportPath`, which also installed it; `simctl runtime add` on the exported dmg then produced a duplicate that was deleted. Booted an iPhone 17 Pro on iOS 26.5, ran `npx expo run:ios`, first build took about 10 minutes. Verified in the simulator: idle screen, start with a name, clock ticking, pause shows Resume and a Paused label. The simulator's keyboard injection drops characters when typing fast, so a name typed as "Chapter 5 Review" landed as "Chapter 5 Re"; not an app bug.
