Integrated in the main thread by rewriting `useTimer` to hydrate from storage, save every transition, and mirror transitions to the Live Activity (start on new session, update on pause/resume, end on stop). Added a `hydrate` reducer action for that.
- Bug in my own spec, caught by the subagent: I gave the running-state example as `timerStartMs: 7000` for `runningSince 10000, accumulatedMs 5000, now 12000`. The correct value is 5000 (`runningSince - accumulatedMs`). The agent implemented `now - accumulatedMs` to match my number, which would only be right at the instant of start. Fixed the formula to `runningSince - accumulatedMs` and dropped the unused `now` parameter.

- Lesson: a standalone `swiftc -typecheck` of the Expo module is not possible because the precompiled `ExpoModulesCore.xcframework` was built with a different Swift version than Xcode 26.6's compiler. The widget files typecheck standalone fine; the module is only verified by the real build.

- Polish items noted for later: the Paused caption clips at the bottom of the expanded island region; the compact leading name could use a wider cap.
- Investigated "lock screen timer stuck at 3:__": reproduced with framebuffer captures at 2, 14 and 26 seconds after locking. The banner reads `7:––` and the last two frames are byte-identical. This is iOS Always-On display behavior, emulated by the iPhone 17 Pro simulator: after the lock screen dims, the system renders `Text(timerInterval:)` with the seconds as dashes and refreshes once per minute; any input wakes the display and seconds return. Not an app bug; Apple's Clock timer does the same. Reference: https://developer.apple.com/forums/thread/735124
- Real bug found during that investigation: the lock-screen `ProgressView(value:)` was computed once at render time and never advanced while running. Replaced with `ProgressView(timerInterval:countsDown:)` for the running state so the system animates it; the paused state keeps the static bar.
- Verified the progress bar fix: after rebuild, the expanded island bar sits at roughly 45% for an 11-minute session against the 25-minute goal, matching the app.
- Gotcha: `npx expo run:ios` fails at its final "open app" step with `LSApplicationWorkspaceErrorDomain error 115` if the simulator is locked, and then never starts Metro. The build and install had succeeded. Recovery: `npx expo start --dev-client`, unlock, and pick the server in the dev client launcher. Keep the simulator unlocked when running the build.
- `@bacons/apple-targets` warns that `ios.appleTeamId` is missing. Harmless for simulator builds; needed only for device signing.
- Edge case observed for free: reinstalling the app while a session was running removed the old Live Activity; on the next foreground launch the app hydrated the session from storage and re-created the activity with the correct elapsed time.

## 2026-09-12, design update

- Received a Claude Design handoff (`docs/design/HANDOFF.md` plus screenshots). Agreed cuts before starting: App Intent buttons in the island, the overflow menu (rename/change goal), the custom goal wheel, Archivo in the widget extension, animations, and the percentage text inside rings.
- Step 0 (foundation), two subagents in parallel plus main-thread work: the reducer gained per-session `goalMs`, `startedAt`, `pauseCount`, a `completed` status with `endedAt`, and a `dismiss` action (100 tests). `goalMs` moved from the ActivityKit attributes into the content state so a goal can change without restarting the activity. Theme tokens and three primitives (`GradientButton`, `ProgressRing`, `Pill`) were built from the handoff tokens. The Live Activity sync rule was extracted into `planLiveActivitySync`, a pure function with tests, to handle the new toggle and the completed state.
- The module now sets `staleDate` to the goal end while running, so the widget re-renders once at that moment and can show "Goal reached" via `context.isStale` without an app update.
- Gotcha fixed pre-emptively: on iOS, `fontWeight` combined with a custom `fontFamily` makes React Native fall back to the system font. All text styles use the weight-specific Archivo family names only.
- Gotcha fixed: the shared-attributes guard test uses Node's `fs`, which had never been typechecked; added `@types/node` and `"node"` to the tsconfig `types` list.
- Step 1 (screens and widget), four subagents in parallel, then integration in the main thread. Bugs found on the first run and fixed:
  - All three screens rendered edge to edge: React Native's `SafeAreaView` on iOS replaces any `padding` you set with the safe-area insets. Moved the padding to an inner `View`.
  - The timer ring overflowed into the status row and controls: the ring wrapper and a bottom spacer both had `flex: 1`, so they split the leftover space and the 286pt ring did not fit its half. Removed the spacer and pinned the status card with `marginTop: 'auto'`.
  - Lock-screen timer and "left" text would not right-align: `Text(timerInterval:)` and relative-date `Text` greedily claim the full row width in SwiftUI. Added `.multilineTextAlignment(.trailing)`.
  - Metro started with `CI=1` disables file watching, so edits never reached the app. Restarted it without CI for hot reload.
- Verified after fixes: first-run screen, new-session sheet with recent chips and goal tiles, timer screen with the SVG ring, Dynamic Island compact (accent name, timer) and expanded (animated ring, STUDYING kicker, goal and live remaining time, large timer).
- What the AI got wrong, raised by the user: the assistant appeared to hang several times and had to be asked "are you stuck?". Cause: `npx expo run:ios` never exits (it stays up as the Metro server after installing the app), and the assistant launched it in the background and waited for a completion signal that could never come. Twice the build output was also piped through a block-buffered filter, so the log looked empty mid-build. Fix agreed: build with `xcodebuild` directly (which exits), keep Metro as a separate long-lived process that is never waited on, poll for concrete signals with bounded loops, and post a one-line status after each background step so silence never means waiting.
- Edge-case step. Serialized the bridge (D8, subagent, 3 new tests, 103 total), added a native same-state check so relaunch keeps the surviving activity, a dev-only 1-minute goal preset, and a dev-only log of the OS activity count after every transition. Built with `xcodebuild` directly this time, which exits, and drove Metro separately; no hangs.
- Verified in the simulator: pause and resume reflected in the app, compact island (amber name, frozen time), expanded island and lock screen; app force-killed with `simctl terminate` while paused, the island kept the paused activity, relaunch re-adopted the session and the log showed the surviving activity was reused (count stayed 1); three rapid start/stop cycles logged `start -> 1` then `end -> 0` every time, app idle at the end.
- Fixed during verification: the trailing-alignment fix for greedy timer text had spread to the expanded island where the large timer and the remaining text should be leading; the text views now take an explicit alignment.
- Not verifiable here: the minimal island presentation needs a second app with a Live Activity in the foreground, and the simulator's Clock app fails to launch (`FBSOpenApplicationServiceErrorDomain 4`). The code path exists (`GoalRing` alone) and typechecks.
- Bug, reported by the user and reproduced with the 1-minute goal: after the goal passed, the island read "24 sec left" and the number grew. The remaining text used `Text(_, style: .relative)`, which counts up again once its date is in the past, and the `staleDate` re-render that was supposed to switch the copy to "Goal reached" never fired in the simulator. Fix: before the goal a countdown `Text(timerInterval:countsDown:true)` ("0:24 left"); after it a count-up from the goal instant ("1:05 over goal"), chosen at render time by comparing the clock with the goal end. Because a widget re-renders only on an update, the app now sends one content-identical update at the goal instant while it is alive; `staleDate` remains the fallback when it is not.
- Verified the over-goal fix with a 1-minute goal: the expanded island read "0:30 over goal" next to a 1:30 elapsed and kept counting, and the lock screen re-rendered to "100% of 1m goal · 1:47 over goal" from the goal-instant update.
- Bug found while re-adopting a session that was already past its goal: the relaunch requested a new activity with a `staleDate` in the past. iOS accepted it (activity count 1) but never displayed it, in the island or on the lock screen. Fix in the module: only set `staleDate` while the goal is still ahead.
- User feedback: the compact island truncated "ios app building" to "ios app b…". That was the 72pt cap from the design spec, not an island limit; raised to 130pt and let iOS truncate on its own.
- Verified the in-app Live Activity toggle: off ends the activity (count 0) and the card reads "Live Activity is off / Timer keeps running in the app"; on restarts it. Note for simulator driving: React Native's `Switch` responded to a slide gesture, not a tap.
